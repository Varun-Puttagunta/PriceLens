# PriceLens AI

A comparable-sales valuation engine and list-price strategist for residential real estate.

It answers two questions a listing agent has to answer every time, and shows its work on both:

1. **What is this house worth?** — built the way an appraisal is built: comparable sales, a
   line-item adjustment grid, a reconciled range, and a confidence grade.
2. **What should it be listed at?** — which is a different question. The price that maximises the
   seller's net proceeds is rarely the biggest number on the page.

Built for a real estate firm, where it supported pricing decisions across **36 properties** and
**$21.8M** in sales volume.

## How the engine works

```
sales book
    │
    ├─ 1. fit ─────── hedonic regression on log(price): recovers the market's drift with
    │                 composition held still, and every adjustment rate along with it
    │
    ├─ 2. select ──── score each candidate sale on location, size, recency, rooms, vintage,
    │                 type; search tiers widen only when the tight grid starves
    │
    ├─ 3. adjust ──── time-adjust each comp, then walk it toward the subject feature by
    │                 feature, in log space so large size gaps stay honest
    │
    ├─ 4. reconcile ─ weight by comparability, penalise heavy adjustment, derive a range and
    │                 a confidence grade from how much the comps disagree
    │
    └─ 5. strategise  sweep candidate asking prices; project days on market, price cuts,
                      carrying cost and final sale price; recommend on net proceeds
```

The part worth pointing at is **step 1**. Most comparative market analyses carry rules of thumb in
from elsewhere — "a bathroom is worth ten thousand dollars" — and apply them to a market that never
said so. PriceLens re-fits every rate from the sales in front of it, every run. On the published
dataset the fit lands at R² 0.976 across 631 sales and recovers a 4.0%/yr market drift.

## Accuracy

Every one of the 36 closed listings is re-priced using only sales that had recorded before it went
on the market, with the property excluded from its own comp set. This runs live on the results page
and in CI:

| | |
|---|---|
| Median absolute error | 5.4% |
| Within 5% of sale price | 47% |
| Within 10% | 83% |
| Closed inside the stated range | 75% |

The range is deliberately not tight. Its coefficients were set so that roughly four sales in five
land inside the band — a narrower range would read better and be a lie.

The results page also names the model's **worst** call in the book, because a model that never
shows you its misses isn't showing you its accuracy either.

## Running it

```bash
npm test          # engine + dataset tests (21 of them, no dependencies)
npm run dev       # serve locally on :8080
npm run data      # regenerate the market dataset
npm run verify-data   # CI guard: data.js must match its generator
```

The test suite plants a known trend in a synthetic market and checks the regression recovers it,
asserts no comparable dated after its subject's listing date can reach an estimate, checks
adjustment signs in both directions, and fails if backtest accuracy or range coverage regresses
past the numbers published on the site.

## About the data

The engagement figures are real: 36 properties, $21.8M in volume.

The individual records are not. Every address, coordinate and transaction in `assets/js/data.js` is
synthetic, generated by `tools/generate-data.mjs` from a hedonic model of a North Dallas market —
client transactions aren't published. The generator's parameters and the engine's are deliberately
different, so the backtest measures the engine recovering a market it wasn't handed.

Portfolio totals are calibrated to the real headline figures so the top line reads true; everything
else is computed from the published data by the same code that runs the tool.

## Layout

```
assets/js/engine.js    the valuation and pricing engine (UMD: browser + node, no deps)
assets/js/charts.js    small SVG chart library — one spec, hover layer, table view for every chart
assets/js/data.js      generated market dataset (do not hand-edit)
assets/css/site.css    design tokens; light and dark are two designed palettes, not an inversion
tools/generate-data.mjs   the market generator
tests/engine.test.mjs     the test suite
```

## Limitations

Stated in full on the [methodology page](methodology.html#limits). The short version: it is not an
appraisal, it cannot see what isn't in the data, it assumes tomorrow resembles last quarter, it
breaks on unusual properties, and the before/after adoption comparison is two consecutive groups
rather than a controlled experiment.
